# 云资源配置指南(域名 / DNS / OSS / CDN / 证书)

后端代码只负责"产物上传 OSS + 返回分享地址",让 `https://{slug}.s.example.com/` 真正能访问,
还需要在云控制台完成以下一次性配置。以**阿里云**为例(腾讯云 EdgeOne、华为云同理,思路一致)。

> 前提:主域名(example.com)已 ICP 备案。国内 CDN/OSS 节点对外提供网站服务必须备案,
> 泛域名接入时核对的是主域的备案状态。

---

## 一、总体链路

```
发布:Agent/用户 ──> Nginx ──> Spring Boot ──上传──> OSS
                                     └─返回 https://{slug}.s.example.com/
                                              └─异步预热 CDN

访问:浏览器 ──> DNS *.s.example.com 泛解析(CNAME) ──> CDN ──回源──> OSS
```

泛域名方案有两条可选链路,二选一:

| | 方案一:CDN 直回源 OSS(推荐) | 方案二:CDN → Nginx → OSS |
|---|---|---|
| 服务器 | 不需要参与静态链路 | 需要一台 Nginx |
| host→路径 改写 | CDN 边缘脚本(EdgeScript) | Nginx map + rewrite |
| OSS 权限 | 私有桶(CDN 自动签名回源)或公共读 | 公共读 |
| 控制力 | 依赖云厂商脚本能力 | 任意 Nginx 逻辑(鉴权/限流/统计) |
| 运维成本 | 低 | 中 |

两条链路的 DNS、OSS、证书配置几乎相同,只在"回源"一步不同。

---

## 二、开通与权限(RAM)

1. 开通 **OSS** 与 **CDN**。
2. 创建 RAM 子账号(或使用 RAM 角色),最小权限:
   - OSS(发布服务用):目标 bucket 的 `oss:PutObject`、`oss:GetObject`、`oss:DeleteObject`、`oss:ListObjects`;
   - CDN(预热/刷新用):`cdn:PushObjectCache`、`cdn:RefreshObjectCaches`;
   - 生产环境将 AK/SK 注入环境变量 `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET`,不要写进配置文件。

## 三、创建 OSS Bucket

1. Bucket 名称如 `artifact-share`,地域选与 CDN 节点就近的(如 cn-hangzhou)。
2. 读写权限:
   - 方案一:选 **私有**,并在 CDN 开启"私有 Bucket 回源"(OSS 会授权 CDN 服务账号读取);
   - 方案二:选 **公共读**(Nginx 无法代签 OSS 请求)。
3. **不要**开启 OSS 的"静态网站托管/默认首页"——入口路由由 CDN/Nginx 改写完成。
4. 可选:开启版本控制(误删可恢复)、配置生命周期规则清理孤儿对象。
5. 建议绑定 Referer 防盗链白名单(允许 `*.s.example.com`,是否允许空 Referer 按需)。

## 四、域名与 DNS(域名管理)

在主域的云解析 DNS 中添加两条记录:

| 主机记录 | 记录类型 | 记录值 | 说明 |
|---|---|---|---|
| `*.s` | CNAME | CDN 分配的加速 CNAME(如 `xxx.w.kunlungr.com`) | 分享泛域名,发布后再添加 |
| `api` | A | 你的服务器 IP | 发布 API(Nginx 反代) |

注意:
- **先在 CDN 添加加速域名、拿到 CNAME 值,再配 DNS**,顺序不要反;
- DNS 通配符 `*.s.example.com` **只匹配一层**,`abc123.s.example.com` 可以,`a.b.s.example.com` 不行——
  正好满足"每个产物一个三级域名"的需求;
- 用 `*.s.example.com`(专用前缀泛域)而不是 `*.example.com`,避免与主域已有解析/邮件记录冲突
  (CNAME 与其他同名记录不能共存);
- 把 `application.yml` 中 `share.domain` 改成你的泛域名后缀。

## 五、CDN 控制台配置

1. **添加加速域名**:`*.s.example.com`(泛域名,整个泛域作为一条加速域名管理),业务类型选"图片小文件"。
2. **源站**(二选一):
   - 方案一:源站选 OSS bucket `artifact-share`;如 bucket 私有,打开"私有 Bucket 回源"开关(OSS 授权后 CDN 自动签名);
   - 方案二:源站选你的 Nginx 服务器 IP(80 端口),即 `deploy/nginx/share-origin.conf` 所在机器。
3. **回源 Host**:与源站匹配即可(方案一回 OSS 时用 bucket 的 endpoint 域名;方案二回 Nginx 时保持默认跟随加速域名)。
4. **缓存规则**:开启"遵循源站"即可——服务上传对象时已设置 Cache-Control
   (HTML `no-cache`,静态资源 `max-age=3600`,可在 `application.yml` 调整)。
5. **HTTPS 证书**:泛域名 `*.s.example.com` 需要**泛域名证书**:
   - 付费:云盾证书(泛域名 DigiCert 等),签好后一键部署到 CDN;
   - 免费:Let's Encrypt / acme.sh 用 DNS-01 验证签 `*.s.example.com`(DNS API 自动续期),
     将证书与私钥上传到 CDN 的 HTTPS 配置。
6. **可选**:Referer 防盗链、单 IP 限流、WAF 等。

### 方案一专属:边缘脚本(EdgeScript)改写回源 URI

CDN 泛域名收到 `abc123.s.example.com/index.html` 时,回源路径要变成 `/s/abc123/index.html`。
在 CDN 控制台 → `*.s.example.com` → **边缘脚本 EdgeScript** 添加一条"请求处理阶段"规则:

```plain
# 伪代码:把子域名(slug)拼进回源路径
# 具体函数名/语法以阿里云 EdgeScript 官方文档为准(capture_re / set_uri 等)
slug = capture_re($host, '^([^.]+)\.s\.example\.com$')
if slug {
    if eq($uri, '/') {
        set_uri(concat('/s/', slug, '/index.html'))
    } else {
        set_uri(concat('/s/', slug, $uri))
    }
}
```

如果你的 CDN 套餐/厂商不支持边缘脚本,或想要更强的控制(按 slug 鉴权、限流、埋点统计),
直接用**方案二**:回源到 Nginx,`deploy/nginx/share-origin.conf` 已实现同样的改写逻辑,开箱可用。

## 六、上线检查清单

- [ ] `mvn package` 产物部署,环境变量注入 AK/SK
- [ ] DNS `*.s` CNAME → CDN 生效(`dig abc123.s.example.com CNAME`)
- [ ] `https://api.example.com/api/v1/artifacts` 可发布(HTTPS + client_max_body_size)
- [ ] 发布测试产物,泛域名能打开 HTML,样式/JS 正常加载(Content-Type 正确)
- [ ] 重新发布同 slug,浏览器拿到新内容(HTML no-cache 生效)
- [ ] DELETE 下线后,分享地址返回 404(CDN 刷新生效)
- [ ] 泛域名证书生效,HTTPS 无告警
- [ ] MySQL 替换 H2(`deploy/sql/schema.sql`),定时备份
- [ ] 内容合规:agent 产物对外公开可访问,建议保留发布记录/操作审计,必要时加人工审核或访问口令

## 七、常见问题

- **打开是下载而不是页面**:对象的 Content-Type 不是 text/html,检查上传时是否带了 `; charset=utf-8`(服务已处理)。
- **样式 404**:agent 产物用了绝对路径(如 `/assets/app.js`),本方案按相对路径寻址;生成产物时尽量用相对路径。
- **重新发布后页面没变**:HTML 若配了 CDN 缓存,需等服务自动刷新(CDN 配置了 warmup/purge)或手动刷新目录。
- **中文文件名 zip 解压乱码**:Windows 打包的 zip 可能把 `share.publish.zip-charset` 改为 `GBK`。
